# 浏览器文件夹上传方案

> 范围：仅浏览器上传相关流程（Koa Web UI + `/upload-base`、`/upload-assets`）。  
> 不含 CLI（`upload-local-files.js`）改动。  
> 文档日期：2026-07-21

---

## 1. 背景与目标

### 1.1 改造前现状

| 能力 | Web | CLI |
|------|-----|-----|
| 单文件上传 | 有 | 有 |
| 递归目录上传 | 无 | 有 |
| 保留相对目录结构 | 无（仅 `targetPath` + 文件名） | 有 |
| 并发上传 | 无 | 有（默认 10） |
| 冲突策略 | `isReplace === 文件名` | 跳过 / 日志 |

Web 页面（`statics/upload-base.html`、`statics/upload-static.html`）仅为单文件 FormData 演示；服务端 `fileUpload` 一次只处理一个 `file` 字段。

### 1.2 目标

在浏览器中支持：

1. 选择整文件夹（或继续单文件）
2. 按文件夹内相对路径写入 OSS，保留目录结构
3. 可控并发与冲突策略（跳过 / 覆盖）
4. 进度与结果汇总

非目标：OSS 直传 STS、multipart 断点续传、空目录占位、HTTP 鉴权（可后续增强）。

---

## 2. 方案选型

### 2.1 推荐：前端拆文件 + 复用现有单文件接口

```
用户选文件夹（webkitdirectory）
  → FileList（含 webkitRelativePath）
  → 客户端并发队列（默认 3）
  → 每个文件 POST /upload-base 或 /upload-assets
       file + targetPath + relativePath + overwritePolicy
  → 服务端拼 OSS key 并 putStream
  → 前端汇总成功 / 跳过 / 失败
```

### 2.2 为何不选其它方案

| 方案 | 结论 |
|------|------|
| 单次 multipart 打包整夹 | 超时、内存、进度差，与现有模型冲突 |
| 新建 `/upload-folder` 批量收齐再上传 | 临时盘易爆，实现重 |
| 仅引导使用 CLI | 不满足浏览器场景 |

## 3. 接口约定

### 3.1 端点（不变）

| Method | Path | OSS 前缀 |
|--------|------|----------|
| POST | `/upload-base` | 桶根 `/` |
| POST | `/upload-assets` | `/assets/` |

### 3.2 请求字段（multipart）

| 字段 | 必填 | 说明 |
|------|------|------|
| `file` | 是 | 单个文件 |
| `targetPath` | 否 | 用户指定的前缀目录 |
| `relativePath` | 否 | 相对路径；缺省用原始文件名 |
| `overwritePolicy` | 否 | `skip`（默认）\| `overwrite` |
| `isReplace` | 否 | **兼容旧逻辑**：等于原始文件名时视为覆盖 |

### 3.3 OSS Key 规则

```
ossKey = join(prefix, targetPath, relativePath)
```

- `prefix`：`""`（base）或 `assets`（assets 路由）
- 统一正斜杠；禁止 `..`、绝对路径、空段恶意路径
- 示例：`targetPath=static/v2`，`relativePath=css/app.css`  
  - base → `static/v2/css/app.css`  
  - assets → `assets/static/v2/css/app.css`

### 3.4 响应

成功：

```json
{
  "code": 200,
  "message": "文件上传成功",
  "data": {
    "name": "app.css",
    "relativePath": "css/app.css",
    "size": 1234,
    "type": "text/css",
    "url": "https://..."
  }
}
```

已存在且策略为 skip：

```json
{
  "code": 409,
  "message": "文件已存在",
  "data": { "name": "...", "relativePath": "...", "url": "..." }
}
```

前端通过 `code === 409` 计为「跳过」（勿依赖 message 文案）。

## 4. 前端设计

### 4.1 页面

- `statics/upload-base.html` → `./upload-base`
- `statics/upload-static.html` → `./upload-assets`

### 4.2 交互

1. **模式**：单文件 / 文件夹（`webkitdirectory` + `multiple`）
2. **预览**：展示相对路径、数量、总大小（最多列 100 条）
3. **冲突策略**：跳过已存在 / 覆盖已存在
4. **并发数**：1～10，默认 3
5. **过滤**：默认忽略 `.DS_Store`、`Thumbs.db`
6. **进度**：已完成 / 总数，以及成功、跳过、失败计数与明细

### 4.3 空目录说明

浏览器 `FileList` 不含空文件夹。OSS 本身也无真实「空目录」对象；本方案不额外上传 `.keep`。

---

## 5. 服务端设计

文件：`src/upload-static-server.js`

1. `normalizeRelativePath`：`\`→`/`，去前导 `/`，拒绝 `..`
2. 用正斜杠拼接 OSS key（不再用 Windows `path.join` 拼对象键）
3. `overwritePolicy` + 兼容 `isReplace`
4. 上传结束（成功 / 失败 / 跳过）后清理 `uploads/` 临时文件

不改动：`ali-oss-uploader.js` 核心、`upload-local-files.js` CLI。

---

## 6. 安全与限制

| 项 | 说明 |
|----|------|
| 路径穿越 | 服务端拒绝含 `..` 的 relativePath / targetPath |
| 单文件大小 | 仍为 2000MB（koa-body） |
| 鉴权 | HTTP 仍无鉴权；批量上传会放大滥用面，后续可加 Token / IP 限制 |
| 临时盘 | 已增加 unlink；大并发仍注意磁盘 |
| 浏览器兼容 | `webkitdirectory` 需 Chromium / Safari 等现代浏览器 |
